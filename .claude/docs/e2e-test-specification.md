## 개요

### 목적
Playwright를 활용한 E2E 테스트를 통해 사용자 워크플로우를 검증하고, 실제 사용자 경험을 시뮬레이션하여 애플리케이션의 품질을 보장합니다.

### 테스트 범위
- 기본 일정 관리 CRUD 워크플로우
- 반복 일정 관리 워크플로우
- 일정 겹침 처리
- 알림 시스템
- 검색 및 필터링
- 드래그 앤 드롭 기능 (신규)
- 날짜 클릭 일정 생성 (신규)

---

## 테스트 환경 설정

### 기본 설정
```typescript
// playwright.config.ts
{
  timeout: 30000,
  retries: CI ? 2 : 0,
  workers: CI ? 1 : undefined,
  baseURL: 'http://localhost:5173'
}
```

### 공통 설정
- 각 테스트는 독립적으로 실행
- `beforeEach`에서 페이지 로드 및 초기화
- `afterEach`에서 데이터 정리 (필요시)
- 스크린샷/비디오: 실패 시에만 저장

## 필수 테스트 항목

### 1. 기본 일정 관리 워크플로우 (CRUD)

#### 파일: `e2e/basic-event-workflow.spec.ts`

#### 테스트 케이스

**1.1 일정 생성 (Create)**
- [ ] 모든 필드 입력하여 일정 생성
- [ ] 성공 메시지 표시 확인
- [ ] 캘린더에 일정 표시 확인
- [ ] 일정 목록에 추가 확인

**1.2 일정 조회 (Read)**
- [ ] 생성된 일정이 캘린더 뷰에 표시
- [ ] 일정 클릭 시 상세 정보 표시
- [ ] 폼에 일정 데이터 자동 채워짐 확인

**1.3 일정 수정 (Update)**
- [ ] 일정 클릭 후 수정 모드 전환
- [ ] 필드 수정 후 저장
- [ ] 성공 메시지 확인
- [ ] 변경사항 즉시 반영 확인

**1.4 일정 삭제 (Delete)**
- [ ] 일정 선택 후 삭제 버튼 클릭
- [ ] 삭제 확인 다이얼로그 표시 (있는 경우)
- [ ] 성공 메시지 확인
- [ ] 캘린더/목록에서 제거 확인

**1.5 유효성 검증**
- [ ] 필수 필드 누락 시 에러 표시
- [ ] 시작 시간 > 종료 시간 시 에러
- [ ] 날짜 형식 검증
- [ ] 시간 형식 검증

### 2. 반복 일정 관리 워크플로우

#### 파일: `e2e/recurring-event-workflow.spec.ts`

#### 테스트 케이스

**2.1 반복 일정 생성 (Create)**
- [ ] 매일 반복 일정 생성
- [ ] 매주 반복 일정 생성 (특정 요일)
- [ ] 매월 반복 일정 생성
- [ ] 반복 종료일 설정
- [ ] 캘린더에 여러 날짜에 걸쳐 표시 확인

**2.2 반복 일정 조회 (Read)**
- [ ] 반복 일정 시리즈 전체 조회
- [ ] 개별 반복 일정 조회
- [ ] 반복 정보 표시 확인 (예: "매주 반복")

**2.3 반복 일정 수정 (Update)**
- [ ] 이 일정만 수정
  - 단일 인스턴스만 변경
  - 다른 반복 일정은 유지
- [ ] 앞으로 모든 일정 수정
  - 선택한 시점부터 모든 일정 변경
  - 이전 일정은 유지
- [ ] 모든 일정 수정
  - 전체 시리즈 변경

**2.4 반복 일정 삭제 (Delete)**
- [ ] 이 일정만 삭제
- [ ] 앞으로 모든 일정 삭제
- [ ] 모든 일정 삭제

**2.5 반복 일정 예외 처리**
- [ ] 반복 일정 중 특정 날짜 건너뛰기
- [ ] 예외 날짜 표시 확인

## 테스트 작성 원칙

### 1. 독립성 (Independence)
- 각 테스트는 다른 테스트에 의존하지 않음
- 테스트 실행 순서에 무관하게 동작
- `beforeEach`에서 필요한 상태 설정

### 2. 반복성 (Repeatability)
- 동일한 입력에 대해 항상 동일한 결과
- 외부 요인(시간, 네트워크 등)에 영향받지 않도록 모킹

### 3. 가독성 (Readability)
- 테스트 이름은 명확하고 구체적으로
- Given-When-Then 패턴 사용
- 주석으로 단계 설명

### 4. 격리성 (Isolation)
- 테스트 간 데이터 공유 금지
- 각 테스트 후 데이터 정리
- LocalStorage/SessionStorage 초기화

### 5. 효율성 (Efficiency)
- 불필요한 대기 시간 최소화
- 적절한 선택자 사용 (data-testid 권장)
- 병렬 실행 가능하도록 설계

### 6. 실제 사용자 시나리오
- 실제 사용자가 하는 행동 시뮬레이션
- 엣지 케이스도 포함
- 에러 상황 처리
